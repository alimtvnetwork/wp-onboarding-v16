# Memory: architecture/coding-standards/control-flow-and-formatting
Updated: 2026-02-21

Code style across all languages (PHP, TypeScript, Go) is governed by a canonical spec at `spec/01-coding-guidelines/code-style.md` (v3.1.0) with thirteen rules: (1) mandatory curly braces `{}` for all control structures, (2) no nested `if` blocks — flatten via combined conditions or early returns, (3) extract any `if` condition with 2+ operators into a named boolean variable, method, or constant, (4) blank line before `return` or `throw` unless it's the sole statement in its block, (5) blank line after `}` when more code follows (exception: consecutive `}` or `else`/`catch`), (6) max 15 lines per function body, (7) reinforced zero-tolerance nested-if ban, (8) no leading backslash on global types, (9) **multi-line arguments for signatures, calls, AND arrays when >2 items** — each argument/item on its own line with trailing comma; applies to function signatures (9a), function/method calls (9b), and PHP array literals (9c), (10) blank line before control structures (`if`/`for`/`foreach`/`while`) when preceded by one or more non-brace statements, (11) long string concatenations must be broken into line-by-line combinations, (12) opening braces for classes, traits, methods, or functions must not be followed by an empty line on the first line of content, (13) source files must not contain an empty line at the very beginning (e.g., immediately following the `<?php` tag).
