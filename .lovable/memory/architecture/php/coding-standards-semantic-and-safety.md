# Memory: architecture/php/coding-standards-semantic-and-safety
Updated: 2026-03-03 (Throwable-first error logging rule added)

Every namespaced PHP file must follow strict statement ordering: `<?php` → PHPDoc header → `namespace` → `if (!defined('ABSPATH')) { exit; }` → `use` imports → class/trait/enum body. The `namespace` declaration **must** appear before the ABSPATH guard — PHP requires `namespace` to be the very first statement after `<?php` and optional `declare`. Placing `if (!defined('ABSPATH'))` before `namespace` causes a fatal `ParseError` at compile time, crashing the entire plugin. The sole exception is `Autoloader.php`, which has no namespace and uses the ABSPATH guard directly after `<?php`. `declare(strict_types=1)` must not be added to individual files unless adopted project-wide — a single file with it creates type-coercion mismatches at trait boundaries.

PHP development targets PHP 8.2+ minimum and follows strict semantic logic and safety standards (v3.1.0). Native PHP 8.1+ backed enums within the RiseupAsia\Enums namespace are mandatory. **Error logging must be Throwable-first**: every error logging method (`logException`, `error_log` in catch blocks) must accept the `Throwable` object as its primary input — not a string message. The message is secondary; the stack trace (`$e->getTraceAsString()`) is the most critical output and must always be logged after `$e->getMessage()` separated by `"\n"`. Logging `$e->getMessage()` alone is a critical defect. The only permitted silent catch blocks are logger recursion guards. See `.lovable/memory/coding-standards/php-exception-handling.md` for full patterns. All early-boot and pre-logger `error_log()` calls must use `InitHelpers::errorLogWithPrefix()` (which prepends `PluginConfigType::LogPrefix`). The only permitted exception is `Autoloader.php`, which must use raw `error_log()` because it executes before the autoloader and helper classes are available. All `wp_remote_get`, `wp_remote_post`, `wp_remote_head`, and `wp_remote_request` option arrays must use `HttpConfigType` static factory methods — inline magic arrays are prohibited. Available factories: `HttpConfigType::headRedirectOptions()` (timeout=15, redirection=0, sslverify=true), `HttpConfigType::defaultGetOptions()` (timeout=30, sslverify=true), `HttpConfigType::authenticatedOptions(string $method, string $authHeader)` (method, Authorization header, timeout=30, sslverify=true). Boolean logic requires semantic inverse methods (e.g., '$plugin->isDisabled()') and semantic guards (e.g., 'isDirMissing()') rather than complex compositions of helpers; trivial `BooleanHelpers` wrappers (`isFalsy`, `isTruthy`, `isNull`, `isSet`, `isEmpty`, `hasContent`) are deprecated since 1.19.0 and prohibited — use native PHP (`!$x`, `(bool)$x`, `$x === null`, `$x !== null`, `empty($x)`, `!empty($x)`) instead. File/directory guards (`isDirMissing`, `isFileMissing`, `isDirExists`, `isDirWritable`, `isDirReadonly`, `isFileExists`, `isFileUnreadable`, `isNotRegularFile`, `isCopyFailed`, `isDirEmpty`) are centralized in `PathHelper` (`RiseupAsia\Helpers\PathHelper`). Non-path domain-specific helpers (`isFuncMissing`, `isClassMissing`, `isExtensionMissing`, `isDbConnected`, `isDbDisconnected`) remain in `BooleanHelpers` (`RiseupAsia\Helpers\BooleanHelpers`). Path resolution is strictly handled via `PathHelper` using typed accessors (e.g., 'getRootDb()') that internally compose directory paths and 'PathEnum' constants; no path fragments or manual concatenation are permitted at call sites. WordPress hooks, REST namespaces, and actions must use constants from 'HookType', 'CapabilityType', and 'HttpMethodType', with all 'RISEUP_' prefixes removed. Descriptively named composed constants (e.g., 'HOOK_AJAX_UPLOAD', 'REST_URL_UPLOAD') must be used at call sites to prevent inline concatenation. Error handling mandates 'catch (Throwable $e)' (no leading backslash), centralized fatal checks via 'ErrorChecker::isFatalError()', and type-label mapping via 'ErrorChecker::getTypeLabel()'. Runtime dependency checks (e.g., PDO/SQLite) must be centralized in 'ErrorChecker' (e.g., 'isInvalidPdoExtension()'). Functions with more than 2 parameters must use multi-line signatures with trailing commas. A blank line is required before `return` or `throw` when preceded by other statements.
